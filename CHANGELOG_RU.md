# Журнал изменений MoodTracker++

Полное описание всех изменений в демонстрационном приложении для изучения различных подходов к персистентности во Flutter.

## Общая концепция проекта

MoodTracker++ - это образовательный проект, демонстрирующий эволюцию Flutter-приложения через различные подходы к сохранению данных. Каждая ветка представляет отдельную технологию персистентности, позволяя изучить их особенности, преимущества и недостатки.

---

## 🌟 Ветка `00_initial` - Базовая версия без персистентности

### Основной функционал
- **Отслеживание настроения** с помощью эмодзи и цветовых индикаторов
- **Отслеживание сна** (время засыпания, пробуждения, длительность)
- **Добавление заметок** к каждой записи настроения
- **Отметка активностей** (спорт, работа, отдых и др.)
- **Статистика и история** записей
- **Переключение тем** (светлая/темная)

### Технические особенности
- Использование Provider для управления состоянием
- Все данные хранятся только в памяти
- Русская локализация для дат
- Material 3 дизайн-система
- Потеря всех данных при перезапуске приложения

### Структура приложения
```
lib/
├── main.dart              # Точка входа приложения
├── models/
│   └── mood_entry.dart    # Модель записи настроения
├── screens/
│   ├── home_screen.dart   # Главный экран
│   ├── add_mood_screen.dart # Добавление записи
│   ├── mood_history_screen.dart # История записей
│   └── statistics_screen.dart # Статистика
└── services/
    └── mood_service.dart  # Управление состоянием
```

### Новые возможности
- **Двойная NoSQL архитектура**: ObjectBox + Realm
- **Высокопроизводительное хранение** записей настроения
- **Полнотекстовый поиск** по записям
- **Система тегов** для категоризации
- **Продвинутая аналитика** с быстрыми запросами
- **Синхронизация между базами**

### Архитектурные решения
- **ObjectBox**: основное хранилище для MoodEntry
- **Realm**: дополнительные данные (активности, теги, статистика)
- Абстрактный слой NoSQLService
- Автоматическая инициализация при запуске
- Кеширование часто используемых данных

### Технические характеристики
- **ObjectBox**: ~1ms вставка, ~0.1ms чтение
- **Realm**: ~2ms вставка, ~0.2ms чтение
- Поддержка 100k+ записей
- Ленивая загрузка для оптимизации памяти
- Реактивные запросы с Stream

### Добавленные пакеты
- `objectbox: ^2.5.1` - NoSQL база данных
- `objectbox_flutter_libs: ^2.5.1` - нативные библиотеки
- `realm_dart: ^1.9.0` - NoSQL база данных Realm

### Что сохраняется

## 🗃️ Ветка `05_sql` - SQL база данных

### Новые возможности
- **5 связанных таблиц** с нормализованной структурой
- **Автоматические миграции** схемы базы данных
- **Raw SQL запросы** для сложной аналитики
- **JOIN запросы** с объединением таблиц
- **Агрегационные функции** (GROUP BY, COUNT, AVG)
- **DDL команды** для управления схемой

### Структура базы данных
1. **mood_entries** - основные записи настроения
   - id (TEXT PRIMARY KEY)
   - mood_value (INTEGER)
   - note (TEXT)
   - photo_path (TEXT)
   - created_at (INTEGER)

2. **sleep_records** - записи о сне
   - id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - mood_entry_id (TEXT REFERENCES mood_entries)
   - hours (REAL)
   - quality (INTEGER)

3. **activities** - справочник активностей
   - id (INTEGER PRIMARY KEY)
   - name (TEXT UNIQUE)
   - icon (TEXT)

4. **mood_activities** - связь many-to-many
   - mood_entry_id (TEXT)
   - activity_id (INTEGER)

5. **statistics** - кешированная статистика
   - id (INTEGER PRIMARY KEY)
   - date (INTEGER)
   - avg_mood (REAL)
   - entry_count (INTEGER)

### Технические особенности
- Type-safe SQL через Drift
- Автоматическая генерация кода
- Поддержка транзакций
- Оптимизированные индексы
- Batch операции

### Добавленные пакеты
- `drift: ^2.16.0` - ORM для SQLite
- `sqlite3_flutter_libs: ^0.5.20` - нативные библиотеки SQLite
- `uuid: ^4.3.3` - генерация UUID

### Что сохраняется
- ✅ Полная реляционная структура данных
- ✅ Связи между таблицами
- ✅ Сложная аналитика через SQL
- ✅ Миграции и версионирование схемы

## ☁️ Ветка `06_cloud_storage` - Облачное хранение

### Новые возможности
- **Cloud Firestore** для реалтайм синхронизации записей
- **Firebase Storage** для хранения фотографий в облаке
- **Автоматическая синхронизация** между устройствами
- **Оффлайн режим** с локальным кешем
- **Сжатие изображений** перед загрузкой
- **Резервное копирование в ZIP** архивы

### Архитектурные решения
- CloudService для работы с Firebase
- Локальные базы как кеш для оффлайн работы
- Очередь загрузок для фотографий
- Обработка конфликтов слияния
- Автоочистка старых фотографий

### Структура данных в облаке
- **Firestore**: коллекция mood_entries с подколлекциями по пользователям
- **Storage**: структура users/{uid}/photos/{timestamp}_{uuid}.jpg
- **Метаданные**: размер, тип, время создания
- **Индексы**: для быстрой сортировки по дате

### Правила безопасности Firebase
```javascript
// Firestore
service cloud.firestore {
  match /databases/{database}/documents {
    match /mood_entries/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}

// Storage  
service firebase.storage {
  match /b/{bucket}/o {
    match /users/{userId}/{allPaths=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

### Добавленные пакеты
- `cloud_firestore: ^5.5.0` - NoSQL облачная база
- `firebase_storage: ^12.4.0` - облачное хранилище файлов

### Что сохраняется
- ✅ Реалтайм синхронизация между устройствами
- ✅ Фотографии в облаке с автосжатием
- ✅ Оффлайн доступ к данным
- ✅ Автоматическое резервное копирование

## 🧹 Ветка `07_clean_data` - Очистка данных

### Новые возможности
- **Комплексная очистка** всех типов хранилищ
- **Безопасный выход** из аккаунта с полной очисткой
- **Отчет об очистке** с детальной статистикой
- **Откат изменений** при ошибках
- **Поэтапная очистка** с приоритетами
- **Соблюдение GDPR** требований

### Типы очистки
1. **Полная очистка** - все данные и настройки
2. **Частичная очистка** - только пользовательские данные
3. **Очистка кеша** - только временные данные
4. **Безопасный выход** - очистка + выход из аккаунта

### Порядок очистки
1. ObjectBox и Realm базы данных
2. SQLite база (Drift)
3. Firestore и Firebase Storage
4. SharedPreferences
5. SecureStorage
6. Локальные файлы
7. Firebase Authentication

### Технические особенности
- Централизованный DataCleanupService
- Подтверждение перед очисткой
- Логирование всех операций
- Обработка ошибок и откаты
- Детальная отчетность

### Структура отчета
```dart
class CleanupResult {
  final int objectBoxDeleted;
  final int realmDeleted; 
  final int sqliteDeleted;
  final int firestoreDeleted;
  final int storageFilesDeleted;
  final int localFilesDeleted;
  final bool preferencesCleared;
  final bool secureStorageCleared;
  final Duration totalTime;
  final List<String> errors;
}
```

### Что очищается
- ✅ Все локальные базы данных
- ✅ Облачные данные пользователя
- ✅ Кеш и временные файлы
- ✅ Настройки и токены
- ✅ Фотографии и резервные копии
